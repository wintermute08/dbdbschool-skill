# 연말 백업·초기화

근거: 제공 매뉴얼 10, 02. 초기화는 되돌릴 수 없는 삭제를 포함한다. 백업 작업 요청만으로 초기화까지 실행하지 않는다.

## 보관할 자료

| 자료 | 제공본 위치·출력 단위 |
|---|---|
| 학생 | 학교관리 > 학생관리, 전체 검색결과 |
| 교직원 | 학교관리 > 교직원관리, 전체 검색결과 |
| 강사 | 강사관리, 전체 검색결과 |
| 강좌 | 강좌관리, 전체 및 구분별 확인 |
| 신청자 | 신청자관리, 모든 강좌구분별 결과 |
| 지원금 대상자 | 지원금관리 > 대상자관리 |
| 지원금 수강자 | 지원금관리 > 수강자관리, 상세 결과 |
| 지원금 월별 사용 | 수강자관리 > 월별현황 |
| 지원금 스쿨뱅킹 | 수강자관리 > 스쿨뱅킹현황, 대상월·강좌구분·금액항목별 |

현재 학교가 사용하는 환불·대기·온라인 출석부·귀가·설문 자료 등 추가 보관 대상도 확인한다. 제공본의 9종 출력만으로 모든 데이터가 보존되었다고 단정하지 않는다.

사용자가 지정한 비공개 보관 위치에 저장한다. 파일별 대상 학년도, 구분/월, 검색 조건, 행 수, 금액 합계, 파일 크기, 다운로드 시각을 기록한다. 파일을 실제 열어 헤더와 표본을 확인하고 누락된 구분이 없는지 대조한다. 다운로드 엑셀은 조회용 백업일 수 있으며 시스템 전체를 자동 복구하는 백업이라고 보장하지 않는다.

## 초기화 범위

학생·교직원은 학교관리의 해당 초기화 화면, 나머지는 방과후학교 `환경설정 > 초기화`에서 관리한다. 학교별 화면을 확인한다.

- 연수지명부를 함께 사용하는 학교는 교직원 전체 초기화를 피하고 필요한 개인별 정리 방법을 사용한다. 서비스 관리자 계정까지 삭제될 수 있다.
- 졸업생만 정리할 때 학년전체를 선택하지 않는다. 재학생 진급과 졸업생 삭제는 별도 업무다.
- 강좌/신청자·대기자·환불자 데이터는 특정 구분과 구분전체를 구별한다.
- 지원금 대상자+수강자 삭제와 수강자만 삭제는 다르다. 후자는 대상자를 유지한다.
- 귀가일정표와 결석/귀가신청은 별개 데이터다.

삭제 대상·건수·보관 파일을 구체화하고 사용자의 기존 승인 범위를 확인한다. 영구 삭제에 대한 도구의 추가 확인 규칙이 있으면 따른다. 삭제 후 해당 범위가 비워지고 보존 대상은 유지되는지 확인한다. 복구 가능성이 불확실한 상태에서 초기화를 시험 삼아 실행하지 않는다.
