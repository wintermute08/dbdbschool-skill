# 수강료·지원금·행정실 출력

근거: 제공 매뉴얼 01의 3·7·8장, 03, 08, 09. 지원 자격과 지급액은 학교의 확정 자료를 입력하는 업무이며 이 스킬이 자격을 심사하지 않는다.

## 금액의 의미와 산출

수강료, 수용비, 강사료, 교재비, 재료비를 따로 확인한다. 수용비 기능을 사용하는 제공본의 관계는 `강사료 = 수강료 − 수용비`다. 수용비를 수강료에 다시 더해 이중 청구하지 않는다. 강좌 기본금액과 신청자 개인금액은 별도이므로 양쪽을 확인한다.

고정 수강료이면 별도의 1/n 산출이 불필요하다. 학교급만으로 결정하지 말고 실제 과금 방식을 확인한다. 1/n 방식이면 `환경설정 > 기본설정`에서 수강료산출 기능, 강좌의 총시수, 인원, 시간당 강사료, 수용비, 조정 기준을 확인한다.

`수강료산출 > 결과 엑셀출력`은 미리보기다. 결과를 검토한 뒤 `결과 수강료 적용`을 해야 학생별 금액이 바뀐다. 반올림·절사 기준을 임의로 만들지 않는다. 적용 후 신청자관리에서 금액을 재조회하고 학생 화면의 수강료 출력 여부도 별도로 확인한다.

## 지원금 처리 순서

1. 강사 조정과 금액 확정을 마친 뒤 대상 강좌의 강사마감을 확인한다. 접수 화면에 표시하는 확정 강좌는 종료로 두고, 분기 분할로 미리 복사해 숨긴 미래 월 강좌는 대기를 유지할 수 있다. 정산을 이유로 모든 강좌를 일괄 노출하지 않는다.
2. `지원금관리 > 지원금설정`에서 지원기간, 지원항목, 차감 순서, 월 한도, 중복 지원 제외 조건과 방식을 확인한다. 제공본의 월 한도 0은 제한 없음이므로 지원 없음과 혼동하지 않는다. 학교 확정값으로 입력한다.
3. `대상자관리`에서 대상자별 총액·기간·순위 등을 확정 자료와 대조한다. 총액을 임의로 부풀리지 않는다.
4. 잔여 금액 차감 방식인지 강좌별 고정 금액 방식인지 구분한다. 후자는 강좌에도 지원금액이 필요하다. 각 강좌의 비용 항목별 지원 제외 여부를 함께 확인한다.
5. `수강자관리 > 수강자 가져오기`에서 대상월·강좌구분을 선택한다. 기존 정산이 있으면 재계산으로 변경될 수 있는 범위와 기존 내역을 확인한다. 선택월 이후 월에 미칠 영향도 확인한다.
6. 대상자별 지원·수익자 부담·잔액, 항목별 총액을 비교한다. 신청자 관리의 확정 금액과 지원금 처리 결과 사이에 설명되지 않는 차이가 없어야 한다.

지원금 순위 구분은 기존 자유수강권 관리와 연동될 수 있다. 한 화면에서 바꾼 값의 다른 업무 영향을 확인한다. 환불 후에는 [refunds.md](refunds.md)에 따라 재정산한다.

## 출력 경로 선택

| 목적 | 제공본 경로·핵심 구분 |
|---|---|
| 지원금 미반영 전체 신청 금액 | 신청자관리 > 신청결과엑셀출력 > 행정실용 |
| 지원금 정산 후 실제 징수 | 지원금관리 > 수강자관리 > 행정실용, 수익자 등 목적에 맞는 출력 대상 |
| 강사료·지원금별 부담 내역 | 지원금관리 > 수강자관리 > 스쿨뱅킹현황 |
| 월별 지원금 사용 | 지원금관리 > 수강자관리 > 월별현황 |
| 나이스 수강생 입력 | 신청결과엑셀출력 > 강좌 기준(나이스입력용) |
| 나이스 수강료 입력 | 신청결과엑셀출력 > 강좌/강사 기준(나이스 수강료 입력용) |
| 지원금 포함 나이스 입력·보관 | 지원금관리 > 수강자관리 > 나이스용, 용도구분 확인 |

나이스 수강료 출력 전에 `환경설정 > 나이스/에듀파인 설정`의 나이스 강좌명 매핑을 확인한다. 강좌/강사 기준은 학교에서 실제 관리하는 단위에 맞춘다. 에듀파인 감면자 입력을 사용할 때만 관련 공통항목을 확인한다.

파일마다 대상 학년도·대상월·강좌구분·늘봄과정·출력대상·금액항목·묶음 단위를 기록한다. 총건수·중복·지원 제외·0원·합계를 확인한다. 한 학생의 여러 강좌 행을 무조건 중복으로 삭제하지 않는다. 생성한 파일이 있다고 실제 징수, 나이스 업로드, 은행 이체가 완료된 것은 아니다.
