# 문자·푸시·설문

근거: 제공 매뉴얼 05, 06, 11, 30. 작성 요청이면 초안까지, 발송 요청이면 지정한 수신자와 내용의 범위에서 진행한다.

## 문자 발송 방식

| 방식 | 전제 | 발송 확인 |
|---|---|---|
| 학교번호 서비스 문자 | 학교관리 > 문자관리의 발신번호 승인, 잔여량, 문자설정·강사 권한 | 문자발송내역 및 상세 결과 |
| 강사 개인 휴대폰 문자 | 모바일에서 해당 강사의 문자 앱 사용 | 문자 앱의 실제 전송 상태 |
| 앱 푸시 | 푸시알림관리, 대상자의 앱 이용 상태 | 서비스의 전송 결과; 수신·열람과 구별 |

`내 폰으로 문자발송`은 서비스가 연락처·본문을 휴대폰 문자 앱에 전달하는 기능이다. 앱이 열렸다는 이유만으로 발송 완료라고 하지 않는다. 학교번호 방식과 비용·발신자가 다르다. 문자 충전이나 발신번호 신규 등록은 발송 작업의 자동 부수 효과로 진행하지 않는다. 충전 단가·무료량·제출서류는 현재 서비스에서 확인한다.

## 대상과 내용

`문자발송(관리)`에서 본문 작성 → 수신자 가져오기 → 대상구분·학년·학급 또는 강좌·신청/대기 구분 확인 → 최종 수신 목록 검토 → 요청 범위의 발송 → 상세 이력 확인으로 진행한다.

- 일반 강좌 대상 발송은 학생당 중복을 줄이는 기능이고 강좌관리의 확정·수강료 안내는 강좌별 발송일 수 있다. 여러 강좌 수강자의 예상 문자 수를 확인한다.
- 신청자와 대기자를 섞어 확정 문자를 보내지 않는다. 학생 연락처와 보호자 연락처를 구별한다.
- 미납금·지원금 안내는 대상자별 변수에 다른 학생의 금액이나 잔액이 들어가지 않았는지 점검한다. 실제 화면의 샘플·변수 삽입 기능을 사용하고 토큰 문법을 만들지 않는다.
- 첨부파일 방식은 최신 수신자 샘플을 사용한다. 이미지·PDF 첨부는 파일 링크로 전달될 수 있으므로 링크의 접근 범위와 개인 정보 포함 여부를 확인한다.
- 발송 결과가 불명확하면 기존 이력부터 확인한다. 전체 재전송으로 중복 문자를 만들지 않는다.

푸시는 `푸시알림관리 > 알림전송`에서 대상·제목·본문과 필요한 수강신청/설문 링크를 지정한다. 초안을 저장한 것과 실제 발송을 구별한다.

## 설문 설계와 집계

`설문관리 > 샘플설문`에서 적합한 샘플을 복사·편집하거나 새로 만든 뒤 `설문관리 > 설문`에서 실제 기간과 대상을 설정한다. 샘플만 만들었다고 실제 설문이 열린 것은 아니다.

| 설문구분 | 대상·집계 기준 |
|---|---|
| 종합 | 전체 학생 대상 수요 조사 등 |
| 강좌 | 해당 수강생, 강좌별 집계 |
| 강좌(강사 ID 기준) | 동일 강사 ID를 묶어 참여·집계 |

별도 집계가 필요한 강좌가 같은 강사 ID인지 사전에 확인한다. 이미 징수·강좌에 연결된 ID를 설문 편의만으로 바꾸지 않는다. 만족도 점수형 문항은 선택지 수와 점수 체계를 통일한다. 제공본에서는 만족도 문항이 일반 문항보다 먼저 표시된다.

설문참여 비밀번호 방식은 해당 설문에서 허용해야 하며 학생 계정 비밀번호와 별개다. 학교가 제공한 현재 안내와 참여 주소를 사용하고 공유 가능한 공개 문서에 실제 비밀번호를 넣지 않는다.

결과보기에서 강좌별·참여자별·전체 합산·만족도 집계 목적을 구분해 출력한다. 강좌 기준과 학생 기준 참여현황을 혼동하지 않는다. 참여·미참여 인원과 집계 단위를 확인한다. 다음 설문을 만들 때 기존 응답 삭제 대신 복사 기능을 우선 검토한다.
