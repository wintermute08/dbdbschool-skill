# 신학기·가학적·진급

근거: 제공 매뉴얼 02, 11의 학적 변경. 메뉴 명칭과 나이스 파일 형식은 현재 화면에서 확인한다.

## 나이스 학적 확정 전 접수

재학생은 기존 학적으로 접수한 후 진급 처리할 수 있다. 신입생은 학교가 생년월일 기반 임시학적 방식을 사용하는 경우 임시 7학년, 반=생월, 번호=생일로 등록한다. `학교관리 > 학생관리 > 기본설정`의 최댓값이 이 방식을 수용하는지 확인한다(제공본: 학년 7, 반 12, 번호 31 이상). 예시 비밀번호를 일괄 적용하지 않고 학교가 정한 로그인 안내를 사용한다.

`학생 일괄입력`에서 신입생 형식의 샘플을 받고 이름·생년월일 등 요구 열을 작성한다. 한글 이름의 불필요한 공백을 확인하되 외국인 이름의 공백·대소문자를 임의 정규화하지 않는다. 등록 결과와 임시학적을 확인한다. 안내문에는 실제 사용 중인 임시학적 방식과 접수기간만 넣는다.

전학생은 신입생과 같은 7학년이라고 단정하지 않는다. 제공본에는 실제 학년과 생월·생일을 결합한 가학적 예시도 있으므로 현재 등록된 값을 기준으로 매핑한다.

## 재학생 진급

1. 기존 학생 목록과 연계된 신청 데이터를 백업한다. 졸업생 정리가 필요한지 확인한다. 졸업이나 진급 누락만으로 학생을 자동 삭제하지 않는다.
2. 나이스의 이전반 기준 반편성 자료를 준비한다. 제공본 경로는 `학적 > 반편성관리 > 반편성조회(이전반 기준)`이며 보고서 형태를 유지한 엑셀이다.
3. `학교관리 > 학생관리 > 진급처리`에서 해당 형식을 사용하고 **고학년부터 저학년 순서**로 처리한다. 예: 5→6, 4→5. 매 단계 잔류 인원을 확인한다.
4. 남은 학생은 전출·유급·매핑 오류 등 원인을 확인한 뒤 별도 처리한다. 예상 인원과 실제 변경 인원을 대조한다.

## 신입생 본학적 전환

생년월일 기반이면 나이스 `학적 > 기본학적관리 > 학년별명렬표출력`에서 생년월일을 포함한 파일을 준비한다. 디비디비 진급처리의 신입생 형식과 실제 임시학년을 선택한다. 이름·생년월일 매핑을 확인하고 불일치·동명이인·누락을 해결한다.

반·번호를 임의 배정했다면 현재 임시학적을 출력하여 이전 학적→정식 학적 매핑 샘플을 작성한다. 신입생 자동 매칭 형식을 억지로 적용하지 않는다.

## 학기 중 번호 변경과 이력 동기화

학생을 삭제·재등록하면 기존 이력 연결이 끊길 수 있다. 기존 학생의 학적을 수정한다. 전체명렬표 방식은 제공본상 학년·반·이름이 같은 학생의 번호를 변경하며 동일 키가 둘 이상이면 자동 변경되지 않는다. 해당 학생은 개별 확인한다.

기본 학적만 바뀌었다고 완료하지 않는다. `환경설정 > 학적검증`에서 대상 구분별 신청자·대기자·온라인 출석부·환불 신청자·지원금 대상자 데이터의 차이를 검증하고, 확인된 학생 정보 변경을 적용한다. 현재 화면에 제공되는 데이터 종류를 모두 점검한다. 최종 신청 이력, 현재 학적, 변경 전후 인원, 미매핑 목록을 대조하고 로그인 번호 변경 안내가 필요한 대상을 정리한다.
